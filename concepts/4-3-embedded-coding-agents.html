Embedded Coding Agents

Giving your product AI-powered code generation and task automation: the Cortex Code SDK lets you embed a coding agent that can write SQL, Python, and orchestration logic -- then execute it -- directly within your SaaS application.

How Companies Accomplish This Today

  • Custom code generation pipelines: Prompt engineering with OpenAI/Anthropic APIs, custom sandboxing for execution, and hand-built UIs for displaying generated code. 6+ months to production-ready.
  • Embedded notebooks: Jupyter-style interfaces embedded in the product (Observable, Hex). Powerful but require technical users and don't integrate with platform governance.
  • No-code workflow builders: Drag-and-drop tools that abstract away code but are limited in expressiveness. Users hit a wall quickly with complex logic.
  • Manual custom development: Customers file tickets asking for custom reports, transformations, or automations. Engineering builds them one-off. Doesn't scale.

Roles and People Involved

Product Engineering

Integrates the Cortex Code SDK into the product UI, manages the execution sandbox, and handles output rendering.

AI / Platform Team

Configures the agent's capabilities, tool access, and guardrails. Decides what the coding agent can and cannot do.

Security / Compliance

Ensures generated code runs within governance boundaries: tenant isolation, resource limits, and data access policies.

End Users (Customers)

Business analysts and ops teams who describe what they need in natural language and get working code/results back without writing it themselves.

Challenges Today

  • Execution sandboxing: Generated code must run safely without accessing other tenants' data or consuming unbounded resources. Building a secure sandbox is hard.
  • Multi-step reasoning: Real automation requires iterating: generate code, run it, observe the result, fix errors, try again. Most LLM integrations are single-shot.
  • Tool access governance: The coding agent needs access to tables, functions, and APIs -- but scoped to the current tenant's permissions. Hard to enforce externally.
  • Cost control: A coding agent that generates and runs expensive queries could blow through a tenant's compute budget in minutes.
  • Quality and reliability: Generated code must be correct, efficient, and idiomatic. Generic LLMs often produce SQL that runs but returns wrong results.

What Snowflake Offers

  • Cortex Code SDK: A programmable coding agent that can write, execute, and iterate on SQL and Python within Snowflake's governance boundary. Embed it in your product via API.
  • Built-in execution environment: Generated code runs inside Snowflake -- no separate sandbox to build. Inherits RBAC, row-access policies, and resource monitors automatically.
  • Multi-turn iteration: The agent observes query results, errors, and schema metadata, then self-corrects. Not just code generation -- code generation + execution + refinement in a loop.
  • Tool-use architecture: The coding agent can read schemas, query data, create objects, and call other Snowflake services (Cortex AI functions, Cortex Search) as part of its workflow.
  • Tenant-scoped by default: Same session-based isolation as Cortex Agents -- the coding agent's session carries tenant context, and all generated SQL is governed by existing policies.

Snowflake Features Used

Cortex Code SDK

Programmable coding agent API. Send a task description, receive generated code + execution results. Supports multi-turn iteration with tool use.

Snowflake SQL Execution

Generated SQL runs natively in Snowflake with full RBAC enforcement. No external execution environment needed.

Session-Based Tenant Isolation

Coding agent sessions carry tenant context. All generated queries are governed by row-access policies and resource monitors.

Schema Introspection

The agent reads INFORMATION_SCHEMA to understand available tables, columns, and types. Produces schema-aware code without hallucinating column names.

Resource Monitors

Limit the compute budget for agent-generated queries. Prevent runaway costs from complex generated code.

Demo Storyboard

1

User Describes a Task

A customer types: "Show me the top 10 customers by revenue this quarter, broken down by product category, with month-over-month growth rates." The embedded coding agent receives this as a task.

2

Agent Explores Schema

The coding agent introspects INFORMATION_SCHEMA to find relevant tables (orders, customers, products), understand column types, and identify join keys.

3

Agent Generates and Executes SQL

Writes a multi-CTE query with window functions for MoM growth. Executes it in the tenant's session. Row-access policy ensures only their data is queried.

4

Agent Iterates on Errors

If the first attempt hits an error (e.g., ambiguous column name), the agent reads the error message, adjusts the SQL, and retries automatically.

5

Results Rendered in Product UI

The final query results are returned to the product frontend and rendered as a formatted table or chart. The generated SQL is shown for transparency.
