One Backend, Any Consumer

A single Snowflake backend serving your web app, analysts in BI tools, developers via API, and AI agents via MCP, with no duplication of data or logic.

The Opportunity

SaaS products are built around a primary UI. But your data has many potential consumers beyond that interface: analysts who prefer Tableau or Power BI, developers querying via REST API, and increasingly, AI coding tools and enterprise agents connecting via MCP. The traditional approach builds a separate integration for each: an API layer for developers, a BI connector for analysts, a webhook for agents. The Snowflake approach is different. The same backend that serves your web app also serves all other consumers, with access patterns added as configuration rather than code. One data model, one governance layer, one place to update, four ways to consume.

Storyboard

1

One Backend

Snowflake holds the canonical data model: governed tables, semantic views, dynamic table aggregations, and business logic as stored procedures. This is the single backend for every consumer that follows.

The key design principle: data governance, tenant isolation, and business logic live in Snowflake once, not in each integration layer. Adding a new consumer means adding a new access pattern, not duplicating the pipeline.
2

Consumer 1: Web App

A Next.js application on Snowflake App Runtime serves your primary customer-facing UI. It queries Snowflake directly using the Snowflake Node.js driver, with OAuth handling user sessions.

See 5.1 for App Runtime deployment. The web app is the highest-control consumer: you own the full UI, feature gating, and user experience.
3

Consumer 2: BI Tools + API

Analysts connect Tableau or Power BI directly to Snowflake using standard drivers. The same semantic views that power the web app serve as the BI semantic layer. Developers use the SQL API for programmatic query access.

See 5.2 for the SQL API and authentication patterns. These consumers read from the same governed data model as the web app; the governance policies enforce tenant isolation automatically.
4

Consumer 3: AI Agents

An MCP server exposes the same data to Claude, Cursor, and enterprise AI tools. Customers with AI coding tools can query their data with natural language without you building a separate integration for each tool.

See 5.2 for CREATE MCP SERVER syntax. The MCP server points at the same Cortex Search services and semantic views as the embedded agent in Section 4. One definition, multiple access modes.
