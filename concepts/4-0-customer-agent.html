Your AI-Powered Customer Agent

An agent that answers customer questions, surfaces insights proactively, and automates workflows, all grounded in your governed Snowflake data.

The Opportunity

Most AI features in SaaS products are passive: they summarize text, classify tickets, or fill in a form field. The next step is an agent that both responds and initiates. Responds when a customer asks "why did my report count drop?", initiates when a usage anomaly is detected before the customer notices. When an agent is grounded in your governed Snowflake data with tenant isolation enforced at the query layer, and AI functions are pre-enriching records in the background, the combined effect is a product that feels attentive rather than just functional. This capstone shows how embedded agents, AI function enrichment, and coding agent automation work as a coherent system.

The Journey

Storyboard

1

The Agent Is Grounded

A Cortex Agent is connected to a semantic view of each customer's data. Tenant isolation is enforced via immutable session attributes, so agent-generated SQL always filters to the calling tenant's data.

See 4.1 for the CREATE AGENT syntax, semantic view setup, and the variables block that passes tenant_id as an immutable session attribute in the agent:run API call.
2

Questions Are Answered

A customer asks "why did my API call volume drop last Tuesday?" The agent traverses the entity model, identifies the relevant time window and affected features, and returns a grounded explanation with supporting data.

The agent uses the semantic view as a Cortex Analyst tool, converting the natural language question into parameterized SQL against the tenant's data. The answer is grounded — no hallucination, because all data comes from Snowflake.
3

Records Are Pre-Enriched

AI functions run continuously in a dynamic table: support tickets are classified and scored, new records are summarized, and anomalies are flagged as they arrive. The agent and the UI query pre-built results.

See 4.2 for the dynamic table pre-enrichment pattern. The key insight: AI function calls happen at ingest time, not at query time. Zero LLM latency when the customer loads the page.
4

Insights Are Pushed

The agent monitors usage patterns and surfaces a proactive insight card when something noteworthy happens: "Your AI credit usage increased 3x this week. Would you like to see which features are driving this?"

Proactive insights come from the pre-enriched dynamic tables (Step 3). A Snowflake Alert fires when a threshold is crossed; your application fetches the generated insight from a pre-built table and renders it in the customer's dashboard without requiring an agent call at render time.
